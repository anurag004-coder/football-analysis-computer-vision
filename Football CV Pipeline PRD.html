1. Problem & Goal

Turn raw broadcast football footage into tactical insight (positions, speeds, passing networks, space control) without manual annotation. Antigravity agents write, run, debug, and iterate on the pipeline; the human defines scope and reviews artifacts.

2. Success Criteria

  • Input: single MP4 clip (broadcast angle) → Output: annotated MP4 + structured tracking data (CSV/Parquet) + 2D tactical map video.
  • Player/ball detection mAP ≥ 0.8 on validation clips; ID switches < 5% of tracks over a 2-min clip.
  • Team classification accuracy ≥ 90% on clear-jersey frames.
  • Homography reprojection error < 3 pixels on labeled pitch keypoints.
  • End-to-end run on a 2-minute 1080p clip completes on target GPU in < 15 min.

3. Non-Goals (v1)

  • Multi-camera fusion, live/streaming inference, referee-decision detection, event/action recognition (passes, shots) beyond basic heuristics.

4. Data Sourcing & Rights

Candidate test footage: 2026 FIFA World Cup and 2025/26 UEFA Champions League broadcasts, since they offer high-quality fixed/slow-panning camera angles well suited to this pipeline.

Important — this is not a copyright clearance. Broadcast footage of both tournaments is copyrighted by FIFA/UEFA and their licensed broadcasters. Using clips (even short ones, even for a personal/non-commercial analytics project) carries real infringement risk; there is no blanket "no copyright issue" status for this kind of footage, and Antigravity's agents should not be instructed to scrape or download broadcast streams. Recommended lower-risk options instead:

  • Open research datasets built for this exact use case, e.g. SoccerNet (tracking/detection clips released for research use under their own license terms — check current terms before use).
  • Footage you own or are licensed to use — e.g. your own recordings of matches you have rights to film, or clips obtained through an official API/licensing deal.
  • Synthetic or stand-in footage (amateur matches, simulated/rendered pitch scenes) for development and testing before pointing the pipeline at anything rights-sensitive.

Treat this as an open item to resolve with actual licensing/legal review before sourcing any tournament broadcast footage; don't have the agent hardcode assumptions about rights clearance.

5. Pipeline Architecture

Phase Process Tech Output
Detection Detect players, refs, ball per frame YOLOv11 (PyTorch) Bounding boxes + confidence per frame
Tracking Persistent IDs across frames, handle occlusion ByteTrack Track IDs linked to detections
Classification Group into Team A / Team B / GK / Ref K-Means on jersey-crop dominant color (HSV) Team label per track
Pitch Mapping Broadcast → top-down 2D map OpenCV homography from pitch keypoints (x, y) pitch coordinates per player/frame
Analytics Positional data → metrics NumPy/SciPy Speed, distance, passing network, Voronoi space control

7. Functional Requirements by Phase

Detection — load YOLOv11 (pretrained or fine-tuned on football dataset), run per-frame inference, output boxes for player/ref/ball classes; configurable confidence threshold. Tracking — feed detections into ByteTrack, output stable track IDs; must recover IDs after short occlusions (< 1s). Classification — crop each player box, extract dominant color via K-Means (k=2-3 to separate jersey/shorts/background), cluster tracks into 2 teams + GK by color distance; persist team label per track for the match (not per frame). Pitch Mapping — allow manual or semi-auto keypoint selection (corners, penalty box, center circle) on first frame; compute homography matrix with OpenCV; project all track centroids to pitch coordinates each frame. Analytics — from pitch-coordinate time series compute: instantaneous & average speed per player, distance covered, Voronoi tessellation per frame for space control, and a passing network (heuristic: ball possession changes between tracks).

10. Risks & Mitigations

  • Jersey color ambiguity (similar kits/lighting): fall back to manual team-color seed input.
  • Ball detection unreliability (small object): consider higher-res crop / dedicated ball-detection fine-tune.
  • Homography drift on moving broadcast camera: re-calibrate keypoints per camera cut, or restrict v1 to fixed/slowly-panning camera clips.
  • GPU cost/availability: cap clip length for dev iteration; batch longer runs.
